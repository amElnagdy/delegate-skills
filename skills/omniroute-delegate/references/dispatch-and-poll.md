# Dispatch and poll

`scripts/relay.mjs` is the canonical dispatcher. It launches Claude through OmniRoute from the
requested repository cwd, sends the brief on stdin, captures stdout/stderr, and writes the shared
`delegate-relay.result.v1` contract.

## Before the first run

```text
omniroute --version
claude --version
node --version
git --version
```

OmniRoute must be running and reachable through its active context or local default
`http://localhost:20128`. The relay never starts OmniRoute and never makes network calls itself.
Credentials come from the active OmniRoute context, `OMNIROUTE_API_KEY`, or explicit launcher flags.
Keep secrets out of briefs and repository files.

## Dispatch

```text
node "<skill-dir>/scripts/relay.mjs" --brief brief.txt --cd /path/to/repo
```

A brief can also be piped on stdin. The relay invokes either:

```text
omniroute launch [--remote URL] [--api-key KEY|--token TOKEN] [--profile NAME] [--port PORT] <Claude args>
omniroute run claude --model PROVIDER/MODEL -- <Claude args>
```

`--model` selects the generic `run claude` form; `--profile` selects a profile generated by
`omniroute setup-claude`. Explicit model/profile values must come from the user, setup output, or
OmniRoute's live catalog.

| Flag | Effect |
| --- | --- |
| `--brief <file>` | Exact brief sent on stdin; omit to pipe it. |
| `--cd <dir>` | OmniRoute/Claude working directory. This is important when project `.claude` context is required. |
| `--out-dir <dir>` | Artifact directory; default is a fresh system-temp directory. |
| `--remote <url>` | OmniRoute remote endpoint. |
| `--api-key <key>` / `--token <token>` | Explicit OmniRoute credential; prefer active context or environment. |
| `--port <port>` | Local OmniRoute port. |
| `--profile <name>` | Claude profile for `omniroute launch`. |
| `--model <provider/model>` | Direct model for `omniroute run claude`. |
| `--timeout <dur>` | Watchdog such as `30m`, `90s`, or `2h`. |
| `--resume-last` | Pass `--continue` to Claude for the latest session in this cwd. |
| `--session <id>` | Pass `--resume <id>` to Claude. Mutually exclusive with `--resume-last`. |
| `--read-only` | Claude plan mode with Read, Glob, and Grep only. |
| `--dangerously-skip-permissions` | Claude bypass mode; mutually exclusive with read-only. |

The relay does not use a direct `claude` fallback. If OmniRoute is unreachable, Claude cannot be
resolved, or the selected route/model is rejected, the run fails and preserves its artifacts.

## Artifacts and result contract

- `brief.txt` — exact brief delivered.
- `events.jsonl` — captured child stdout; OmniRoute may emit plain text or JSON events.
- `final.txt` — final report text, including plain-text fallback output.
- `stderr.txt` — complete stderr, including OmniRoute diagnostics.
- `result.json` — `delegate-relay.result.v1` with status, exit code, signal, session id, final report,
  touched-file placeholder, artifact paths, timestamps, and redacted launcher metadata.

The relay blocks until the child exits. Completion requires both a terminal process exit and a
`result.json`. A zero exit code with an OmniRoute/Claude error in stderr must still be reviewed.
An empty `finalMessage` requires inspection of `events.jsonl` and the working-tree diff.

## Windows and project context

The relay passes `--cd` to the child process. Use the repository root when OmniRoute or Claude relies
on `.claude` files, profiles, hooks, or project trust. OmniRoute versions may differ in resolving
`claude.cmd` versus `claude.exe`; preserve the exact error and follow the installed version's
supported workaround rather than bypassing OmniRoute.

## Resume and failure recovery

Use `--session <id>` when several sessions exist; use `--resume-last` only when the latest session
for the same cwd is unambiguous. After failure or timeout, inspect the working tree and artifacts
before retrying. Never reset or clean partial work automatically.
